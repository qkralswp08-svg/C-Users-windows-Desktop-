# paper-analyzer

## 목적
논문 한 편을 "요약" 이 아니라 "재현·비교·활용" 이 가능할 정도로 분해한다. 이 프로젝트(3-Level NPC, DC-link 커패시터 노화, 전류 고조파, CNN)에 무엇을 가져올 수 있는지까지 연결한다.

## 언제 사용하는가
- `papers/pdf/` 에 넣은 PDF 분석, DOI/URL 로 지정한 논문 분석
- `literature-researcher` 가 선정한 핵심 논문 정독
- 특정 주장(예: 특정 고조파 성분)이 논문 본문에 실제로 있는지 확인

## 입력 확보
- PDF: `papers/pdf/` 에서 `Read` 로 읽는다 (페이지 단위, 긴 논문은 절 단위로 나눠 읽기). 텍스트 추출이 안 되면 그 사실을 알린다.
- URL/DOI: `WebFetch` 로 공개 본문/초록을 가져온다. 페이월이면 초록·공개 버전만 분석하고 범위를 명시한다.

## 분석 순서 (모든 항목을 채우되, 논문에 없으면 "논문에 없음")
1. 연구 목적
2. 기존 방법의 문제점 (저자가 지적한 것)
3. 제안 방법 (한 문단)
4. 시스템 구조 (토폴로지, 커패시터 종류/정격, 센서 위치)
5. 중요한 수식 (번호, 식, 각 변수의 정의)
6. 변수의 물리적 의미 (프로젝트 변수명과 대응 가능하면 표기)
7. Figure 해석 (핵심 그림 3~5개: 무엇을 보여주고 무엇을 주장하는지)
8. Waveform 해석 (시간영역 파형의 형태·대칭성·주기)
9. Spectrum 해석 (어떤 성분이 언급되는지, 차수, 크기, 조건)
10. 실험 조건 (정격, 부하, 스위칭 주파수, 샘플링, 온도, 노화 모사 방법)
11. Simulation 조건 (도구, 모델, 파라미터)
12. Algorithm 단계 (의사코드 수준)
13. 입력 신호 (측정/계산, 센서 수, 샘플링)
14. 출력 결과 (추정 오차, 정확도, 비교 대상)
15. 장점
16. 한계 (저자 인정 + 분석자 판단, 구분 표기)
17. 현재 프로젝트에서 활용 가능성 (신호·feature·구현·비교실험·보고서 관련연구)

## 출력 형식
- 위 17 항목을 번호 그대로 사용한 구조화 노트
- 각 항목 끝에 근거 위치(절/식/그림 번호/페이지)를 적는다.
- 마지막에 **사실 / 해석 / 추론** 요약 3줄, **프로젝트 To-Do** 3개 이내
- 노트를 `papers/notes/<연도>-<제1저자>-<짧은제목>.md` 로 저장하고 `papers/index.md` 의 해당 행에 노트 링크를 추가한다.

## 주의사항
- 논문이 직접 말한 것과 분석자의 해석을 같은 문장에 섞지 않는다. 해석은 "(해석)" 또는 "(추론)" 을 붙인다.
- 수식은 논문 표기를 유지하고, 프로젝트 변수와의 대응은 별도 표로 만든다.
- 그림을 읽을 수 없으면(스캔 PDF 등) "그림 미확인" 으로 남긴다.

## 다른 Skill과의 조합
